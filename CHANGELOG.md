# Changelog

Completed backlog items move here from `.claude/napkin.md`'s Backlog category, most recent first. Napkin keeps only pending work; this file is the history.

## Unreleased

- **[2026-07-26] Progression: local save, trophies, Fleet Rank, Voyage Road, Doubloons** — `Assets/Scripts/Core/Progression/`: `SaveProfile`/`SaveService` (atomic-write JSON at `Application.persistentDataPath`, corrupt saves quarantined instead of silently overwritten), `FleetRankCatalog`/`VoyageRoadCatalog` (id-keyed tier/node data), `ProgressionService` (trophy rate table per connection mode, derived account total/Fleet Rank, Sailor unlock, first-win-of-day, level-ups). `Session` gained the connection-mode field Plan 00 always specified but never had. Wired into `M1PrototypeBootstrap`: a match's result now actually updates the save on `OnMatchEnd`.
- **[2026-07-26] Fixed a residual order-dependence in the simultaneous-double-knockout tie-break** — the first fix (award the round to whichever knockout was reported last) turned out to still be order-dependent for a genuine mutual kill (two different attackers, one per team, each landing the other side's final blow the same tick — the only way a double-wipe can happen here, since nothing in `Gameplay/Combat` allows friendly fire). Now tracks which team(s) scored knockouts in the batch: a wipe from one team's attackers only awards that team, a wipe with attackers from both sides has no principled winner and replays the round instead.
- **[2026-07-26] Round reset + deterministic round-end + knockout attribution** — `MatchController` now fires `OnRoundReset` at the start of every round, and `SailorPawn.ResetForRound` restores HP/ammo/collider/rendering and repositions to spawn (Super charge carried over per `MatchRules.SuperChargeCarryoverFraction`) — closing the gap where `MatchRules.Default`'s best-of-3 was inert past round 1. `ReportKnockout` now takes an explicit attacker id and defers survivor evaluation to the next `Tick()`, and lifetime per-attacker knockout counts are tallied for the Progression work above.
- **[2026-07-26] Fixed two review-flagged bugs in the same day's Core/Networking work** — `LanSessionScanner` was calling `JsonUtility.FromJson` from the background thread `UdpClient.BeginReceive`'s callback runs on (not safe off Unity's main thread); it now queues raw bytes there and parses/stores them from `Tick()` instead. `MatchController.EndRound` could recurse synchronously into starting the next round when `RoundResetDelay` is 0, letting a second same-tick knockout misattribute itself to the round that had just silently started; it now always defers the next round to the following `Tick()` call.
- **[2026-07-26] LAN session discovery (UDP broadcast/scan)** — `Assets/Scripts/Networking/Discovery/`: `SessionAdvertisement` (versioned wire format), `LanSessionAdvertiser` (host broadcasts to port 47777 every ~1s), `LanSessionScanner` (client aggregates/expires discovered sessions). No Netcode for GameObjects dependency yet — this is the standalone discovery layer the Local Network mode's lobby UI will list sessions from. `NetworkInputDriver`, `LobbyState`, `LanSessionLauncher`, and connection-approval/rejoin logic remain unbuilt.
- **[2026-07-26] `MatchController` now implements the real Sink or Swim state machine** — `Setup → RoundCountdown → Combat (with a Rising Tide sudden-death sub-state on a survivor-count timeout tie) → RoundEnd → (next round | MatchEnd) → Results`, best-of-3 via `MatchRules.Default`, and a new `ArenaCatalog` (single `tideline-cove` entry) that `Session`/mode launchers reference by id instead of hardcoding arena names. The M1 prototype's single-round, no-timer behavior is preserved unchanged via `MatchRules.M1Defaults`. `SaveService`/`ProgressionService` remain unbuilt (tracked separately in the napkin backlog).
- **[2026-07-19] Prototype now playable on Android, with real touch controls** — left-side virtual joystick to move, right side drag-to-aim/hold-to-fire, and a Super button zone above it, matching the intended mobile control scheme. Also fixed the Android build actually rendering anything (it was silently running on the wrong graphics pipeline before) and a device-only bug where the game objects' hitboxes failed to attach. Editor testing still uses keyboard/mouse for faster iteration; touch is what runs on-device.
- **[2026-07-18] First playable prototype: Ensign Ace vs. Admiral Anchor** — a local, Editor-only build where you can move, aim, and fight as either Sailor. Ace fires a ranged 3-shot Jump Serve burst; Anchor swings a close-range Anchor Slam that knocks enemies back, and once its Super charges up, leaps in with Drop Anchor for impact damage plus a temporary damage-reduction shield for nearby allies. Knockouts end the match. Keyboard/mouse only for now — no touch controls or on-device build yet, and the arena is a placeholder greybox, not the real Tideline Cove.
- **[2026-07-18] Bootstrap the Unity project** — Unity 6000.5.4f1 LTS opened and building for Android: IL2CPP/ARM64, URP, Input System (New), custom base Gradle template (kotlin-stdlib duplicate-class fix), Optimized Frame Pacing disabled (Swappy/Vulkan emulator crash workaround). Confirmed running on `Pixel_9_API_35` emulator.
